# v1.14.0 — The journal and the board: e2e-traceable runs over `.orchestrate/`

> **Status:** implemented — v1.14.0. Design date: 2026-09-15. Base: v1.13.1.

**Through-line:** the user wants to *see* a run — which task is where, who is on it — in a
terminal pane next to the controller, on any host (Claude Code, Codex, Grok, opencode, Pi). The
obvious build is a `tasks.json` that every agent updates. That build contradicts the pack's own
invariants (*observation ≠ transition*, *reports are claims; the disk is the record*), races
across worktrees, and asks eight different CLIs to edit JSON reliably. So the board is a **view**,
and the only new state is one append-only line per fact the disk cannot already show.

## Decisions

1. **Derive, don't duplicate.** Todo ← `task-N-brief.md` / `card-<k>.md`. Review ← `task-N-report.md`
   or `review-taskN-<kind>-rK.md` (verdict read from the findings file's first ✅/❌/⚠️). Done ←
   a `progress.md` line — final, always wins. Blocked ← a report whose status is `BLOCKED` /
   `NEEDS_CONTEXT`. Only what the disk cannot show needs a record: `journal.jsonl`.
2. **Newest fact wins** across disk mtimes and event timestamps, so a fix-wave re-dispatch after
   a report lands correctly moves the card back to in-progress, and a later findings file moves it
   forward again. Gate verdicts are timestamp-ordered too; `--reset-gates` starts a fresh cycle.
3. **The controller is the single writer of transitions.** It already dispatches, records BASE,
   and appends the ledger — each of those is one extra `board …` call. A worker saying "done" is
   a proposal; the gate passing is the transition. Workers may only `board note` (heartbeat).
   This keeps the byte-identical WORKER/REVIEWER blocks untouched (the note line lives in the
   priming anatomy's report contract) and means no engine ever has to be taught the state model.
4. **The user owns the pane.** No `board open`, no terminal detection. Ghostty on macOS has no
   split IPC (`+new-window` is Linux/D-Bus only; community tools fake keystrokes through the
   Accessibility API). A new split/tab inherits the cwd everywhere that matters, and the script
   resolves the workspace through `git rev-parse --git-common-dir`, so a pane opened inside a
   worker's worktree still shows the run. The flight plan prints the command every run.
5. **Reachable without PATH surgery.** `install.sh` copies the script to `~/.local/bin/board`
   (skipped, with a message, if a foreign `board` is already on PATH); `scripts/workspace` also
   drops a copy at `.orchestrate/board`, refreshed whenever the skill's copy is newer.
6. **Stdlib only.** python3, raw ANSI (curses was the first cut — see Rejected); mtime-signature polling at 500 ms; no
   daemon, no hooks, no TUI framework. One dashboard is still worth less than one good ledger.

## Second iteration: the journal (same day)

The board alone left the run without a **spine**: `run.md` was prose the LLM composed, the
flight plan was re-composed each run, nothing recorded returns, escalations or decisions in
order, and the header could only regex `run.md`. So `board.jsonl` became `journal.jsonl` — the
run's append-only journal — and every view derives from it:

7. **One stream, controller-written, at steps that already exist.** `init` (the `run` record +
   todo cards), `plan <outcome>`, `dispatch`, `return` (the typed status, commits, report,
   observed model, tokens), `review`, `nudge`/`escalate`, `decide` (mirrors into
   `decisions.md`), `rail`, `finish`. Workers still only `note`.
8. **`run.md`'s structured part is generated.** `board init` writes a `## Resolved` block between
   HTML-comment markers; `plan`/`return --observed-model`/`rail` update it; prose lives below.
   The flight plan is now literally `run.md` rendered: `board plan` builds the topology tree per
   strategy (staged/xcli/advisor repeating unit, parallel one worker per card + integrator, loop
   cycles, hierarchical/team/adversarial/workflow shapes, generic fallback) and the footer strips
   from the record, and the controller adds only the triage why (`--why`).
9. **Derived counters instead of bookkeeping.** Budget used = dispatch events / ledger `Cycle`
   lines / Σ return tokens against the caps in the record; model drift = requested tier vs the
   `observed_model` a return carried, keyed by role→tier.
10. **Mechanized ledger rules.** `board check` lists dispatched-never-returned, stale in-progress,
    report-without-review, ledger lines naming commits (`git cat-file`) or artifacts that don't
    exist, tasks skipped while later ones are done, drift, budget overrun and `finish` with open
    tasks — exit 1 while any remain, so it can gate "finish".
11. **The handoff's state layer is generated.** `board resume` prints goal, per-task state,
    decisions, pointers and open work in `shared-handoff.md`'s order; the controller adds the WHY.
12. **Self-tested.** `board --selftest` replays a staged run in a temp repo through every command
    and asserts each derivation (including the `board.jsonl` → `journal.jsonl` migration); it
    runs inside `scripts/check-sync`.

## Surface

```
board · show · agents · log · plan · check · resume · path          (views, all derived)
board init PLAN --strategy S [--review --engine --host --models r=t,.. --effort --isolation
                --trigger --workers --budget agents=9,tokens=.. --confirm --alias --goal "…"]
board plan approved|changed|skipped [--msg]
board dispatch N --agent A [--role --model --engine --effort --worktree --reset-gates --msg]
board return N --agent A --status DONE|DONE_WITH_CONCERNS|NEEDS_CONTEXT|BLOCKED
                [--commits a..b --report PATH --observed-model M --tokens 84k --msg]
board review N --kind spec|quality|… [--round K --agent A --model M]
board nudge N --agent A · board escalate N --agent A --to MODEL --why "…"
board decide ID "msg" [--owner --task] · board rail "msg" · board finish --gate pass|fail [--evidence]
board blocked N --msg … · board done N · board note N MSG [--agent A]
```

Raw-ANSI truecolor painter (alt-screen, single-write frames, `SIGWINCH`, unicode-width-aware
clipping, meta wraps under the title on narrow panes); markers are ASCII (`>` running, `!`
stale, `ok`/`fail`/`warn`/`..` gates). `! stale 12m` replaces `>` when an in-progress card's
artifacts have not changed for ten minutes — monitoring rule 3b made visible.

## Rejected

- **Worker-written `tasks.json`** — races, drift, and a second source of truth that the ledger
  would then have to be reconciled against.
- **Hooks (`SubagentStop` → board)** — Claude-Code-only; the controller call is host-neutral.
- **`board open` with a per-terminal ladder** — fragile on the user's primary terminal, and it
  makes the skill responsible for a UI surface it cannot observe.
- **curses** — the only stdlib TUI framework, but 8/16 colours in practice and fiddly widths; a
  raw-ANSI painter is ~80 lines we own with truecolor and exact cell control.
- **A `tasks.json` schema the LLM edits** — the journal is written only through the script's
  flags, so no host ever has to be taught the state model or edit JSON.
