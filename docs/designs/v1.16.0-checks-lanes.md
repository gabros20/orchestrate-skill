# v1.16.0 — Checks, lanes, receipts: the board learns what a run actually did

> **Status:** implemented — v1.16.0. Design date: 2026-09-16. Base: v1.15.0. Research:
> [../research/2026-09-review-sweep.md](../research/2026-09-review-sweep.md).

**Through-line:** after v1.15 the journal was a spine, but three things a factory needs were
still outside it. Tests and scripts ran unrecorded (a running `npm test` was just "in progress"
— and no agent kanban surveyed does better); a subprocess lane's session id lived in the
controller's memory, so `board resume` could only tell the next controller to go and find it;
and the flight plan's budget line said "state a range" because nothing priced the tree. The
release puts all three on the record without touching the invariants: the journal is still
controller-written, the ledger still final, the board still a view.

## Decisions

1. **Checks are journal facts with a badge, not a lane.** Every CI/PR tool surveyed keeps a small
   canonical state under a pipeline-generated graph and gives checks their *own* surface (GitHub
   Checks: grouped rows, duration, rerun). `board exec N --name tests -- <cmd>` runs the check
   through the journal (`check` start/finish events, log under `raw/`, exit + duration), the card
   shows `tests ok 12s · lint fail`, the header counts `checks 3/4 ok`, a failure is an `x` in
   attention and refuses `board done` like a failed gate. `board result` journals a check that ran
   elsewhere. Checks are keyed to the attempt like gates: a fix wave starts them over.
2. **Lanes are a projection of state × role, declared or defaulted.** `--lanes …` is a run dim
   (`todo/done/blocked` required); a card's lane is its canonical state refined by the open
   stint's role (verifier → verify, integrator → integrate, reviewer → review, running check with
   no stint → verify). No per-strategy lane table, so nothing can drift from `board plan`; a run
   with no `--lanes` renders exactly as before, and `--selftest` asserts both.
3. **The session id is a stint field.** `board dispatch --session --log --cmd-file` (or `return
   --session`) — the roster shows it, the expanded card shows the lane, and `board resume` prints
   the engine's resume-by-id line per open lane from one table (`RESUME_CMD`), `NOT_PROVEN` when
   no id was journaled. Hygiene rule 4 becomes "pre-pin where the engine allows" (Grok `-s`,
   Claude `--session-id`), the live probe's best find.
4. **The flight plan is priced from receipts.** `board plan` counts tree nodes per tier and
   multiplies by the p50/p90 of every `--tokens` return in `.orchestrate/archive/*/journal.jsonl`
   (past runs only — the current run must not price itself), printing the band with its
   provenance; no receipts → the honest "state a range". A `lane` line previews the subprocess
   engine's launch pre-configured from the record (`LAUNCH_CMD`).
5. **The record is a gate (governance floor).** `board check` fails a task marked done with no
   reviewer ever opened (review on), a quality gate opened while spec is not ok, an xcli DONE with
   no receipt, a third implementer attempt with no `escalate` event — judged on roles and order
   alone, never on worker text (open-multi-agent's "governance floor"). `board check --replay`
   derives every card from the journal alone and diffs the disk view: a fact that reached the disk
   without its journal line is a finding, `inconclusive` where the pointers are archived.
6. **Cost per accepted outcome, and a postmortem that recommends.** `RUN COMPLETE` and the resume
   receipt carry tokens per accepted task; `board postmortem` tallies per-tier dispatches,
   attempts, drift, escalations, tokens, checks — and suggests at most one routing change, only on
   repeated evidence, never applied (the BTFR rule). The loop evolve pass takes it as input.
7. **One file per engine.** The 2.9k-token catalog becomes nine ~400-token blocks plus an index
   holding the cross-engine session / resume / receipt / cap / hermetic-flag map; SKILL.md links
   every block directly (the lint's flat-reference rule). Every block was re-verified live where
   the CLI is installed and docs-checked where not, with the drift corrected (Claude
   `--max-turns`, Codex `mcp-server`, `web_search`, Grok models and `-p`).

8. **Older workspaces are adopted, never restarted.** A workspace has a shape the tool can read
   (empty · pre-journal · open · finished). A bare `board init` over live work would have archived
   the ledger and re-queued every task — the compaction failure mode the pack warns about — so it
   now refuses and prints the two routes: `--resume` adopts (journal started over the existing
   artifacts, `adopt` line journaled, Resolved block above the prose, `--replay` treats
   pre-adoption history as inconclusive), `--fresh` archives on purpose. `board check` names a
   pre-journal workspace and a stale zero-install `board` copy, so an agent arriving with a newer
   skill is told what it found before it acts.

## Rejected / deferred

- **Strategy-derived lane tables** — duplicates `board plan`'s topology logic and must be kept in
  sync; the role projection gives the same picture from data the journal already has.
- **A `verify` lane by default** — most runs have no verifier stint; declared lanes keep the default
  board unchanged for existing users.
- **Dollar pricing in the cost band** — the pack carries no per-model price facts; tokens per tier
  from receipts are evidence, dollars would be a guess. Claude's `--max-budget-usd` is the lane
  cap where dollars matter.
- **Dropping the reference preambles / `## Contents` blocks** — required by `scripts/lint-skill`;
  the token win (~1.3k across the pack, ~90 per file read) is not worth loosening the lint.
- Still deferred from v1.15: nested child journals; splitting `shared-token-economy.md`.
