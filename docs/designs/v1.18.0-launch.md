# v1.18.0 — Launch, piggyback delivery, follow: closing the gap between what the skill says and what the controller types

> **Status:** implemented — v1.18.0. Design date: 2026-09-16. Base: v1.17.1. Evidence: the first
> live two-Grok mail run (v1.17.0) — the agents did everything right; the controller made two
> shell mistakes and hand-wrote five things the board already knew.

## Decisions

1. **The lane is one command, from one table.** `ENGINES` holds, per engine, an argv *list*
   (no quoting bugs), how the prompt travels (stdin · flag · text), where the session id comes
   from (`pin` — the board mints it; `stream` — read from the log after exit), and how the
   receipt is fetched. `board launch` renders the wrapper, journals the dispatch with everything
   the resume and receipt paths need, starts the lane detached, and the wrapper's last line is
   `board lane-exit`, which journals `exit` and `receipt`. Both are **observations** (like `note`
   and `check`): the controller still records the return — status is judgment, not a process
   exit code. Approval and sandbox flags are deliberately absent from the table; `--extra` is the
   controller saying "I chose this".
2. **`run.tokens` is a sum over stints.** Receipts may land before or after the return (or be
   amended), so the run total is derived at the end of `load()`, never accumulated.
3. **Delivery rides on the worker's own calls.** `deliver()` runs at the end of every worker-side
   command: unread mail is printed and acked. The rule's cost drops from four inbox calls to two
   while delivery becomes *more* frequent; the guarantee ("next board call") is stronger than
   "next checkpoint" and still needs no host feature.
4. **Rails can be derived.** The record already implies "shared tree, two writers"; the board
   states the consequence (commit by path, never -A) in the plan and header without a journal
   line — stated, never silent, and never a fact someone has to remember to write.
5. **The controller's watch is the journal.** `board follow` is a filtered tail with a
   `--for controller` view; hooks and monitors get a stable line-per-event feed instead of
   hand-rolled `tail | grep | python` pipelines (which is what failed live).
6. **Report ↔ return is a note, not a gate.** The report's `Status:` is captured beside the
   controller's status; disagreement is visible in the postmortem. Refusing would invert the
   invariant (the worker's status is a proposal).

## Rejected

- Auto-recording the return from the exit code — an exit 0 with an empty diff is `REFUSED`, not
  `DONE`; only the controller can say which.
- Approval flags in the engine table — they would make the safe default unsafe for the sake of
  convenience; `--extra` keeps the choice explicit and journaled (the wrapper is on disk).
- Creating worktrees in `launch` — isolation stays `shared-isolation.md`'s concern; `--cwd`
  points a lane at one.
