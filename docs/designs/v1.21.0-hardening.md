# v1.21.0 — Hardening: what five live runs and a cold read of the pack said to fix

> **Status:** implemented — v1.21.0. Design date: 2026-09-16. Base: v1.20.1. Evidence: the
> two-lane mail run, the team run, three todo-app runs (v1.17–1.20), and a fresh read of
> `board`, the 42 references, the six scripts, `check-sync` and `install.sh`.

## Verdict

The design is right and finished; the work is hardening, verification and trimming, not
features. The ethos holds — markdown the controller reads, stdlib scripts it points at, artifacts
on disk, the controller records transitions, workers observe. Mail is CLI-agnostic by
construction (a worker appends a line to a locked file; the engine never participates), proved
loop-proof and idle when the record is complete. The only engine-specific code is `board launch`.

Deliberately not built: per-recipient mailboxes, nested child journals, push delivery, dollar
pricing, worktree creation inside `launch`, a leaner xcli WORKER block (a byte-identity change
that deserves its own release).

## Findings and decisions

1. **A dependency that cannot land was invisible to the waiter.** `dep_landed()` treated any
   return as landed, so a BLOCKED/REFUSED dependency *released* the waiter and a gated lane
   started its engine on a missing input; a dependency lane that died with no report never
   landed, so the waiter slept forever with no release but the controller's return — which
   triggered the first bug. Decision: `dep_failed()` is a first-class outcome. `wait --task`
   exits 3; the wrapper maps it to lane exit 125 and never starts the engine; attention names
   the fix (`return … BLOCKED`, repair the dependency, relaunch); gate exits fetch no receipt.
2. **Read-only lanes crashed.** Codex `--sandbox read-only` and Claude `--restricted` cannot
   write the journal; every worker-side command raised a traceback into the model's context.
   Decision: `observe()` wraps worker-side writes and degrades to a printed line the worker
   carries in its inline return; `vote` prints the exact vote line for the controller.
3. **Evidence loss on re-run.** `exec` overwrote `raw/check-taskN-<name>.log`. Decision: one
   log per run, keyed by the running event's journal seq.
4. **The help was two releases stale** and SKILL.md step 6 had become a command manual.
   Decision: the docstring is grouped by role, the selftest fails when a subparser is missing
   from it, and the skill text points at `board --help` instead of listing.
5. **`board` on PATH was assumed** inside lanes; from a worktree `.orchestrate/board` does not
   exist. Decision: the wrapper exports `ORCHESTRATE_WS` and prepends the board's directory to
   PATH. Native subagents inherit the host's PATH (`install.sh` puts `board` in `~/.local/bin`).
6. **Harness streams are not a watch.** Lane exits arrived 10–17 minutes late twice. Decision:
   the documented controller primitive is a blocking `board wait --task N --timeout 0` in a
   background shell; streams are a convenience on top.
7. **Stop conditions read as advice** — both todo-app frontends started the backend they were
   told not to. Decision: the anatomy says hard prohibitions go under Scope → Must NOT, IN CAPS;
   the card schema carries a Must NOT slot; a replicated-invariant line guards it.
8. **`--after` had to be remembered.** Decision: `brief-check` prints every read↔write
   dependency across a batch as a hint, and the parallel strategy says *wait late, not early*.
9. **Release chain failed open twice.** Decision: `scripts/release` refuses at the first gate
   that is not true; `install.sh all` covers every CLI home that exists.
10. **Verification honesty.** The engine map says how far each launch template is verified;
    only a live lane upgrades `dry-run` to `live`.

## Token economy (assessed, not changed)

Priming is near its floor for progressive disclosure (~22k tokens for a typical xcli run, paid
once and cached). The three references over the 2,500-token review threshold are read by the
controller, not by workers. Per-lane cost on Grok (~550k on toy tasks) is the engine re-sending
context per tool call; the skill's lever there is fewer worker tool calls, which piggyback
delivery already does, and `--after`, which removed the waiting cost entirely.
