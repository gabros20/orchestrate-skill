# v1.26.0 — reap: what a run leaves running

> **Status:** implemented — v1.26.0, 2026-09-23. Prompted by a Grok session found polling a repo
> 18 days after its turn and four orphaned node servers from a week-old Claude session.

## Evidence (live, 2026-09-23)

One lane per engine, briefed to background a sleeper and return:

| Engine | its own helpers after exit | what the agent backgrounded |
|---|---|---|
| Grok 4.7 | gone | survives — new session, env scrubbed, ppid 1 |
| Claude Code | gone | survives — same |
| Codex | gone | killed by the sandbox |

Only the cwd and the start time link a survivor to its lane. macOS `ps` elapsed time rounds, so a
start estimate is ±1s — slack is symmetric.

## Decisions

- **Ownership** = in a journaled lane's tree or group (wrapper pid verified by start), or an
  orphan whose cwd is in the run's trees (repo, worktrees, journaled lane cwds) and started after
  kickoff. Owner = stint whose root holds the cwd (most specific wins) and whose window holds the
  start. Verdict: live (an owner open) · left (all owners closed) · unknown (no stint) · kept.
- **Never touched**: caller's ancestry, `board` calls (the controller's own waits), another run's
  tree (nearest journal above the cwd), tty-attached trees, shared daemons (Codex app-server,
  Grok leader, tmux/screen/zellij, desktop apps), anything before kickoff.
- **Listing is free, killing is named**: `--kill` → left; `--agent A` → A's sole-owned live/left
  (an open lane stopped engine-first); `--all` → everything (kill switch); shared owners only by
  `--pid`. Every pid re-verified (start + command) before TERM, KILL after the grace.
- **Detection where it is cheap**: `lane-exit` scans once (twice, 2s apart, to let engines finish
  their own cleanup) and journals `leftover`; the pane only signals pid 0. `check`, `finish` and
  `resume` scan live; the pane never scans.
- Workers: one WORKER sentence; inside a lane `reap --kill` is limited to the caller's own.

## Not covered

A process an agent starts outside the run's trees (a global daemon, `cd /tmp && …`): the WORKER
sentence asks the report to name it. Non-POSIX hosts: the scan says it is unavailable, `check`
notes it, nothing blocks.
