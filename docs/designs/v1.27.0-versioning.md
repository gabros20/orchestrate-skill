# v1.27.0 — versioning: the runtime and every run know their release

> **Status:** implemented — v1.27.0, 2026-09-23. Prompted by a Codex agent that could not certify
> which release it ran ("the on-disk skill does not publish a release string") and queued a
> migration nothing required.

## Decisions

- **One release, five places, one guard.** `skills/orchestrate/VERSION`, the board's `VERSION`,
  plugin.json, the CHANGELOG top and the `MIGRATIONS` top; `scripts/bump` sets the first three,
  check-sync fails unless all agree, `scripts/release` gates on VERSION. `SKILL.md` stays
  version-free (no churn in the text agents read).
- **Every event carries `v`.** A run's release = its run event's `v`; unstamped = pre-1.27.
  Mixed writers = an older (or unstamped) event after a newer one — a stale copy on a lane's PATH.
- **Migration lines, not migration code.** One line per release: `none` (additive — upgrade in
  place) or `action` (a check finding, so finish refuses, until `board version --ack`). Journal
  rewrites never live there; they run on open, like the v1→v2 upgrade.
- **Compatibility contract.** `SCHEMA` bumps only for a breaking change, with an upgrader. An older
  board refuses to write a newer-schema journal, and its upgrader never rewrites one (it used to:
  fixed). An older release writing a newer run only warns — additive events are safe to ignore.
- **Surfaces.** `board version [--json]`, `board --version`, a `check` note, a `resume` line, and
  path-skew / stale-copy notes that name both versions.

## Not covered

Copies installed before 1.27 print no version (`--version` is an error there) — "unversioned
(<1.27)" is what newer boards call them.
