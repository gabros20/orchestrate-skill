# v1.29.0 — replan: reality over plan, redesign never patch

> **Status:** implemented — v1.29.0, 2026-09-29.

## Problem

Workers comply. When a plan's assumption fails, a worker that was told to "continue with the task
as asked" patches around the failure to reach DONE. The skill had BLOCKED → "plan wrong → human",
but no signal distinct from BLOCKED, no definition of a patch, no redesign role, and no line
between internal design (an architect may decide) and product behavior (the user decides).

## Decisions

- **A status, not a note.** `DESIGN_CONFLICT` is machine-visible: it halts the task and its gated
  dependents (building on a broken design is waste) and stays open on the board until a decision
  names the task or the task is re-briefed.
- **The dispatcher owns it.** Lineage routes it: a lead resolves conflicts inside its domain; a
  conflict crossing a domain or a shared interface climbs to the controller.
- **Three-way triage.** Brief (fix, re-dispatch) · design (architect pass) · product (the user).
  Unsure between design and product → product.
- **Fresh architect over the controller.** The controller is anchored on the plan that failed and
  carries run noise; a fresh strongest-tier model with a packet judges better. It writes a delta,
  never code; decisions propagate through `board decide --why` (supersession, `(revised)` in
  running workers' digests) — no new delivery mechanism.
- **Bounded.** Two architect passes, then the user; each pass must change something.
- **Reviews close the loop.** Quality catches patches, spec catches silent redesigns.

## Not covered

A worker that patches and reports DONE anyway is caught only by review; the quality lens names
the patch patterns so the reviewer can see it.
