# v1.32.0 — review convergence, proof first, workers in scope

> **Status:** implemented — v1.32.0, 2026-10-30.

## Problem

Review loops had no end condition except "zero findings" or a round cap. A fresh reviewer samples
differently every round, so a round rarely comes back empty even when the code improves: a finding
the controller had already dismissed could fail the next round, and two or three such rounds
escalated the worker's model although the worker was not the cause. The coverage rule gave all
triage to the controller without saying what a dismissal needs. A `panel:3` gate passed on two ok
votes while the third lens never reported. Workers at high effort started their own review rounds
and fixed things outside their task, and a plan resting on an unrun assumption could sink a whole
wave before anyone found out.

## Decisions

- **Settled stays settled, on the controller's side.** A finding dismissed with evidence the
  reviewer could read (`file:line`, a decision id, command output) is journaled on the gate
  (`board gate … --msg "settled: …"`) and stays closed in later rounds. Reviewers never see the list
  — telling them would pre-judge. No new board command: the gate's `--msg` already journals.
- **A fix does not settle.** The same issue back at the same place means the fix failed — reopen.
  A round is clean with no unsettled Critical/Important; only unclean rounds count toward the
  model-tier escalation.
- **Churn is a trade-off, not a round.** A new finding that undoing the last fix would resolve
  goes to replan triage (brief · design · product), never another review round.
- **Never lower a severity; never write code to quiet a reviewer.** Evidence the reviewer could
  not see goes into the record (`board decide`) or to the user.
- **A missing lens is a hole.** A panel passes only once every lens voted; `board done` refuses a
  vote-pending gate (`.. k/N`); the controller retries the lens once, then closes the gate naming
  the gap. Evaluated at command time, so old journals are not re-flagged (migration `none`).
- **Restate before judging a plan.** The plan reviewer and the counter-planner first state what the
  plan builds and how the parts connect; a part that does not connect is a finding.
- **Proof first.** Several tasks resting on an assumption nobody has run in this stack → one thin
  end-to-end task in the first implementation wave, with a hard edge from the tasks that rest on it.
- **Workers in scope.** Change only what the task needs; list the rest under Noticed, not touched;
  stop when the checks pass, with no self-started review rounds (vendor testing: about a third off
  max-effort session cost at equal quality).
