# v1.33.0 — board truth: a flight plan the user sees, one derivation of "open", a lean CLI

> **Status:** implemented — v1.33.0, 2026-10-30.

## Problem

Measured on 14 real Claude Code sessions (1,373 board calls):

- **The flight plan never reached the user** — 5 of 5 `board plan` calls. Agents piped it through
  `tail -25`, then recorded `plan approved --msg "…plan printed"` (it was only in tool output, which
  the user does not see), or asked "Approve this flight plan?" without showing it.
- **The board said things that were no longer true.** A brief touched 0.1 s after its dispatch put
  the task back in TODO (`Task.state` raced file mtimes against journal timestamps); a ledgered task
  kept its unreturned agent "stale 477h"; questions from workers that had returned ten days earlier
  stayed "the worker may be waiting"; the header said RUN COMPLETE while `check` said a task was open.
- **Tokens went to the manual.** `board --help` cost ~7k characters per read (12 reads); a wrong flag
  dumped the whole usage; the board's command vocabulary was written three times on the controller's
  path (~2.9k tokens).
- **The header grew without bound** (17 lines on one run, 7 of them pause/resume notes stored as
  rails), and its attention strip showed counts, not the action.

## Decisions

- **The tool holds the flight-plan line, not prose.** `board dispatch` and `launch` refuse while a
  resolved run's plan is pending. The plan is ≤ ~22 lines, ends with a relay line ("the user cannot
  see tool output — paste this whole block"), and `board plan --ask` prints the AskUserQuestion
  payload whose Approve option previews the plan. No approval flag recording "shown": agents add
  flags reflexively and a flag proves nothing (advisor disagreement, resolved for the mechanical gate).
- **Journal transitions own a card's state;** disk facts only refine it (a brief seeds `todo` only for
  a task the journal never named; a report moves a task on only when newer than its last transition).
- **The ledger closes what it outlived.** A stint whose task reached the ledger before it returned is
  `closed, no return` — never stale, never someone waiting. Twins on one task (racing two lanes) are
  never auto-closed, and a failed finish does not close live workers.
- **One finish predicate**: `finish_invalid` includes open tasks, so header, `check`, `memory` and
  `resume` agree (`RUN COMPLETE (OPEN WORK)`).
- **`board next`** is the controller's checkpoint (≤ 15 lines, reads, never acks) instead of chaining
  `attention` + `inbox` + `check`.
- **Help from one source**: the docstring's role sections → `board help` (a ~900-character index),
  `board help controller|lead|worker|views`, `board COMMAND --help`; a parse error is one line.
- **References keep semantics, the CLI keeps syntax**: SKILL.md step 5, the contracts' journal section
  and the monitoring board section were rewritten around `board next` / `board help`; the WORKER block
  uses `send --ask --wait`, and every role writes one visible line before a long command (text, not
  thinking — the 5.5 models hide inter-tool text in thinking blocks): ≈758 tokens per dispatch.
- **`board hold`** makes the user's pause run state (HELD), not a rail. The live header is bounded
  (~8 lines: the top action spelled out, the latest rail plus "+N earlier"); `e` / `show -x` expands.
- Durations in days, dates on times not from today, backticks stripped from titles, all-empty roster
  columns hidden, roles normalized, removed workspaces dropped from `board runs`.
