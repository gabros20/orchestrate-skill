# v1.37.0 — worker cards: the role's contract is handed over by the tool

> **Status:** implemented — v1.37.0, 2026-11-01 (released). Ledger E-2026-10-31-e (and E-c).

## Problem

The bench's first baseline gave three results:

- **No report files.** Not one of the 24 build returns carried `--report` or a confidence, and no
  build workspace held a single report file.
- **Ad-hoc worker prompts.** Every worker prompt inspected was a ~750-character task text. None
  carried the WORKER or REVIEWER block, the report contract or a `Confidence:` line.
- **Help reads.** 11 of 27 replays grepped `board help controller` for the gate or review syntax.

`SKILL.md` step 5 said "always through the role's prompt template", and it was skipped in every run.
That one rule carries everything a worker gets:

- the work log;
- the visible line before long commands (v1.33);
- the report file, the status protocol and the stop rules;
- the calibration line (v1.34).

Prose that costs the controller ~1.5k output tokens per dispatch loses to a short hand-written prompt
whenever there is any pressure.

## Paths considered

| Path | Why not / why |
|---|---|
| Infer the report path at `return` | Nothing to infer: no report files existed |
| More prose ("always paste the template") | That is the rule being skipped; v1.33 showed prose loses to tool output |
| A host hook injecting the contract into Agent calls | Claude Code only: settings-dependent, not portable to Codex or Grok lanes |
| Workers discover the board on their own | Circular: the instruction to do so lives in the block that never arrives |
| **The board writes a card and prints one line to hand over** | **Chosen.** It costs the controller one line instead of ~1.5k tokens, and the worker reads the contract as cheap, cacheable input |

## Decisions

- **`board dispatch` writes the card.** So do `board review --agent` and `board launch`. The card is
  `.orchestrate/prompts/<agent>.md`:
  - **A header:** agent, role, task, run, the absolute brief path, and the report path
    (`task-N-report.md`, or `review-task<N>-<kind>-r<R>.md` for reviewers, the name the board
    already parses for verdicts).
  - **Board identity:** `--agent` and observe-only.
  - **The role template's dispatch fence, verbatim,** read at dispatch time from the skill's own
    references. That is one source of truth, and `check-sync` already keeps its block byte-identical.

  The line printed is "the agent's prompt starts with: Read <card> first".
- **A launched lane gets the card prepended** to its spec, unless the spec already carries the
  contract.
- **`return` and `gate` read the card's paths** when `--report` / `--findings` are absent.
  Calibration therefore needs no controller memory.
- **`dispatch` takes the role from the agent's name** when `--role` is absent (`spec-3` → spec
  reviewer). This is E-c, observed when a reviewer dispatch reset a task's review cycle.
- **`attention` and `next` print the exact command:** the review to dispatch, with agent name and the
  run's reviewer model, then the gate line. "Gates passed" now points at `board done N`.
- **`SKILL.md` step 5 and staged step 1 point at the card.** `SKILL.md` is 13 tokens smaller; the
  `board learn` invariant moved to the worker's side, where the card carries it.
- **The skill root is found** beside the script, then through `ORCHESTRATE_SKILL`, the repo's project
  skill and the installed copies. A copy at the board's own release is preferred. With no
  references found, the card degrades to header plus a pointer.

## Measured

Replays, v1.36.0 against the candidate `e501eb4`, Sonnet:

- **dispatch-card** (the worker reads its card and a report with `Confidence:` lands): **0/3 → 3/3**.
  Confidence was journaled at return on 1/3 → 3/3.
- **The other eight cases** (board-checkpoint, concurrency-default, panel-missing-lens, overload-safety,
  report-landed, plan-pending, finish-retro, resume-activation) were **identical on both sides**.
  overload-safety was 1/2 on both: a 6-turn budget spent reading.
- **Help reads:** 11/15 → 9/15, unproven at this n.
- **Cost:** $2.63 → $2.71 for 15 replays. Mean turns 7.1 → 6.5.

Fan-out builds, v1.36.0 (2 runs) against the candidate (5 runs):

- **Confidence at return:** 0/8 → 17/18 on orchestrated builds. Calibration now has data: Brier
  ≈0.01, bias −0.10, so the workers were slightly underconfident.
- **Hidden tests:** every build passed all of them.
- **Triage:** 2 candidate builds went solo by triage, against 7/8 orchestrated before. The next 3
  orchestrated, which is chance at this n.
- **Orchestrated cost:** $0.42–0.75 against $0.31–0.49.
- **Wall time:** 414–650 s against 91–344 s. Unproven at this n; a watch item for field data.

## Bench changes found on the way

- The grader reads worker-side events (`expect_worker`), files (`expect_files`), and counts before a
  marker (`expect_count`).
- A variable is read as `board` only when the command set it to a board path; a loop's `$n` had read
  as `board`.
- Matching is case-insensitive where agents vary ("Task 2", "Module 2").
- `bench clean` removes only unreferenced workdirs. A hand-rolled `rm` had deleted earlier replay
  transcripts; their graded results survive in `bench/results/`.
